# BOSS 适配器维护说明

当前适配器尚未完成真实账号联调。默认 CSS 类名是待核验的候选选择器，模拟页面只验证代码逻辑。**本项目没有宣称当前 BOSS DOM 与这些选择器一致。**

## 执行流程

1. 在独立、可见的持久化 Chromium / Chrome / Edge 中由用户扫码登录。
2. 从用户打开的独立职位详情页读取名称、公司、薪资、城市及描述。
3. 执行时重新打开详情，验证公司、职位及最新匹配条件。
4. 若显示「继续沟通」，交给人工核对；否则唯一识别「立即沟通」并点击一次。
5. 等待「继续沟通」或聊天区域出现；没有确认信号则暂停。
6. 附件模式下，仅当会话显示完整匹配的公司与职位时，才打开简历选择器。
7. 选择完整文件名唯一匹配的附件并确认发送，要求新增的自己发送消息同时包含文件名和配置的成功文本。

流程的任何一步出现缺失、多个匹配、验证或超时都会转为待核对。不会反复点击、盲选附件或轮换账号。

## 更新选择器

`config/boss-selectors.json` 集中定义了职位、聊天区、简历行、已发送消息等定位方式。只应配置**当前已观察到的 DOM**，不要为了让程序继续运行而放宽接收方或成功回执判断。

推荐复制到 `data/boss-selectors.local.json`，更新后通过环境变量 `BOSS_SELECTORS` 指向该文件，避免把账号相关信息提交 Git。

```powershell
$env:BOSS_SELECTORS = 'data/boss-selectors.local.json'
npm start
```

关键约束：

- `chatPanel` 必须唯一表示当前会话，不能匹配联系人列表和隐藏会话。
- `chatJobTitle` / `chatCompany` 相对于当前会话查找，文本必须精确匹配采集结果。
- `resumeDialog` 应匹配单个弹窗外层，不能同时命中嵌套层。
- `resumeRow` 相对于简历弹窗查找；名称要求完整精确匹配。
- `sentMessages` 只可匹配自己发送的消息，不能匹配对方消息或简历选择菜单。
- `resumeSuccessText` 必须是已发送消息的实际确认文案。

无法仅靠选择器覆盖的变化（iframe、新标签页聊天、额外确认弹窗）需要修改 `src/boss.js` 并补充对应测试。

## 联调顺序

先验证手动采集，再选择单个职位验证仅沟通模式；核对实际结果后，最后验证附件模式。联调会涉及真实招聘者，请只选择确实想申请的职位。

异常截图位于 `data/screenshots/<职位ID>.png`，可能含有个人信息。反馈问题时优先提交脱敏 HTML 片段、版本和错误文字，勿上传登录会话或原始聊天截图。
